API 키는 유료 결제 수단이 연결된 '신용카드'이자 '우리 집 디지털 도어록 비밀번호'입니다.

이 비밀번호를 코드에 직접 적지 않고 .env라는 별도의 비밀 금고에 넣어두는 핵심 이유는 3가지입니다.

1. 깃허브(GitHub)를 통한 해킹 및 과금 폭탄 방지 (가장 중요한 보안)
코드에 직접 적었을 때 (하드코딩):

여행 계획 프로그램을 만들고 GitHub에 자랑스럽게 올리는 순간, 전 세계 해커들이 만든 자동 검색 봇이 1초 만에 API 키를 긁어갑니다.

내 카카오/Gemini 계정으로 수십만 건의 호출을 마구 날려서 하룻밤 사이에 수백~수천만 원의 요금 폭탄이 청구될 수 있습니다.

.env로 분리했을 때:

비밀 키는 내 컴퓨터의 .env 파일에만 꼭꼭 숨겨두고, Git에게 ".env 파일은 절대 인터넷에 올리지 마!"라고 지침서(.gitignore)에 적어둡니다.

이렇게 하면 프로그램 코드만 올라가고, 열쇠는 내 컴퓨터에만 안전하게 남습니다.


2. '프로그램(기계)'과 '열쇠(비밀번호)'의 분리 (편리함과 유지보수)
비유: 자동차를 새로 샀다고 해서 매번 엔진이나 차체 구조를 뜯어고칠 필요가 없는 것과 같습니다.
차 키만 바꾸면 됩니다.

실제 개발:

나중에 API 키가 만료되거나 다른 계정의 키로 바꿀 때, travel_planner.py 코드를 한 줄도 건드릴 필요가 없습니다.

오직 메모장 같은 .env 파일의 키 값 한 줄만 바꿔 적으면 프로그램이 알아서 새 키를 읽어옵니다.


3. 협업과 배포 환경에 따른 유연성
팀 프로젝트를 하거나 다른 사람에게 내 코드를 공유할 때:

내 개인 카드로 결제되는 API 키까지 넘겨줄 수는 없습니다.

코드는 그대로 공유하고, 상대방에게는 "너의 API 키를 각자의 .env 파일에 넣어서 써라"고
안내(README.md)만 해주면 됩니다.



API 키는 과금과 직결되는 민감한 자산

소스 코드 안에 키를 직접 하드코딩해 두면 GitHub에 푸시했을 때 외부에 즉시 노출되어
도용이나 과금 피해가 발생할 수 있습니다.

따라서 비밀 키는 로컬의 .env 파일에 보관하고, .gitignore로 추적을 제외하여 원격 저장소 유출을 차단했습니다.

또한 프로그램 코드와 환경 설정을 분리함으로써, 추후 키가 변경되더라도 코드를 수정할 필요 없이
설정 파일만 변경하여 유연하게 대처할 수 있도록 설계했습니다."

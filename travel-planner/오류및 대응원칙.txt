1. 인증 오류 (Authentication / Authorization)
상태 코드: 401 Unauthorized, 403 Forbidden

비유:

401: "신분증(API 키)을 아예 안 가져왔거나 엉뚱한 가짜 신분증을 낸 상태"

403: "신분증은 맞는데, VIP 라운지 출입 권한(지도 서비스 활성화)이 꺼져 있어서 문전박대당한 상태"

실제 프로젝트 사례:

카카오 로컬 API를 호출했을 때 API 키는 맞게 넣었지만, 카카오 개발자 콘솔에서 OPEN_MAP_AND_LOCAL disabled 오류(403)가 떴던 경우입니다.


대응 원칙:

401이나 403 코드가 오면 즉시 사용자에게 "API 키 또는 개발자 콘솔 권한 설정을 확인하세요"라는 명확한 안내 메시지를 띄웁니다.

프로그램이 빨간 글씨 에러를 내며 강제 종료(Crash)되지 않도록 try-except로 감싸고, 빈 리스트([])를 반환해 프로그램의 나머지 단계가 멈추지 않도록 처리합니다.




2. 쿼터/사용량 초과 오류 (Rate Limit / Quota Exceeded)
상태 코드: 429 Too Many Requests

비유: 놀이공원에서 한 시간에 탈 수 있는 놀이기구 횟수가 5번인데, 10번 연속으로 타려고 해서 입구에서 제지당한 상태

발생 원인: 무료 API 플랜의 분당/일일 호출 한도를 넘겼거나, 너무 빠른 속도로 반복 호출(루프)을 날렸을 때 발생합니다.


대응 원칙:

결과 캐싱(Caching) 도입: 오늘 구현한 보너스 과제처럼, 이미 한 번 받아온 날짜 데이터는 로컬 JSON 파일(results/{date}_raw_data.json)에 저장해 두고 중복 호출을 원천 차단하여 사용량을 아낍니다.

대기 후 재시도(Backoff): 429가 발생하면 1~2초간 프로그램에 휴식(time.sleep())을 준 뒤 재요청하도록 설계합니다.




3. 네트워크 / 통신 오류 (Network Error / Timeout)
상태 코드: 서버 응답 자체가 안 옴 (ConnectionError, Timeout)

비유: 전화를 걸었는데 상대방 전화기가 꺼져 있거나 터널에 들어가서 아예 신호가 안 가는 상태

발생 원인: 내 컴퓨터 인터넷이 끊겼거나, 카카오나 구글 서버가 일시적인 점검/장애 상태일 때 발생합니다.


대응 원칙:

타임아웃(Timeout) 필수 지정: requests.get(..., timeout=5)처럼 최대 대기 시간을 반드시 걸어둡니다. (타임아웃이 없으면 인터넷이 끊겼을 때 프로그램이 무한정 멈춰버립니다.)

대체 데이터(Fallback) 제공: 통신이 완전히 끊기면 "네트워크 연결을 확인하세요"라는 메시지와 함께 프로그램이 안전하게 종료되도록 방어합니다.




4. 데이터 파싱 오류 (Parsing Error / Model Error)
상태 코드 / 에러명: JSONDecodeError, 404 NOT_FOUND

비유: 주방장(AI)에게 "숫자로만 적어서 줘"라고 했는데 한글 줄글을 섞어서 써 보내 서류 심사 기계가 고장 난 상태

실제 프로젝트 사례:

Gemini가 JSON 앞뒤에 설명 문장이나 마크다운 백틱(```json)을 붙여 보내서 파이썬의 json.loads()가 에러를 뿜을 때.

예전 모델(gemini-2.5-flash)이 서비스 종료되어 404 NOT_FOUND 에러가 발생했던 경우.


대응 원칙:

정규식 전처리: LLM 출력 문자열에서 마크다운 백틱(```)과 불필요한 줄바꿈을 정규식으로 깨끗이 깎아냅니다.

자동 재시도(Retry): 파싱에 실패하면 1회 더 LLM을 호출해 다시 올바른 JSON을 받아오도록 기회를 줍니다.

Fallback(기본값) 보장: 재시도마저 실패하더라도 프로그램이 죽지 않도록 코드에 미리 준비해 둔 '기본 추천 도시(강릉, 경주)'를 대신 채택하여 최종 리포트 생성을 완주합니다.



외부 API는 언제든 실패할 수 있다는 전제 하에 4가지 대응 원칙을 적용

첫째, **인증 오류(401/403)**는 카카오 지도 서비스 비활성화 이슈를 직접 겪으며 확인했고,
상태 코드를 분기 처리해 사용자에게 원인을 명확히 안내

둘째, **쿼터 초과(429)**는 동일 날짜 재실행 시
로컬 JSON 데이터를 재사용하는 결과 캐싱 로직으로 외부 호출 자체를 최소화

셋째, 네트워크 지연에 대비해 모든 요청에 timeout=5를 걸어 무한 대기를 차단

넷째, LLM의 JSON 파싱 실패에 대비해 정규식 전처리, 1회 자동 재시도,
그리고 실패 시에도 프로그램이 끝까지 돌 수 있도록 기본 대체(Fallback) 데이터를 마련해 시스템 안정성을 확보
